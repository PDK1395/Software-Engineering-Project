# TrackFlow | مدیریت انبار و فروش با بارکد

**TrackFlow** یک پروژهٔ درس مهندسی نرم‌افزار برای ثبت کالا، کنترل موجودی و ثبت فروش با اسکن بارکد است. این مخزن شامل مستندات محصول، الگوهای اسپرینت و یک نمونهٔ اولیهٔ قابل اجرا در مرورگر است؛ نمونهٔ فعلی برای نمایش گردش کار است و هنوز پایگاه داده یا اتصال واقعی به بارکدخوان ندارد.

> زبان مستندات: فارسی. نام فایل‌ها و ساختار مخزن انگلیسی نگه داشته شده‌اند تا در GitHub استاندارد باشند.

## قابلیت‌های هدف
- تعریف کالا با نام، SKU/بارکد، قیمت و نقطهٔ سفارش
- جست‌وجوی سریع کالا با تایپ یا بارکدخوان USB (که مانند صفحه‌کلید ورودی می‌فرستد)
- ثبت ورود/خروج موجودی و نگهداری تاریخچهٔ تغییرات
- ساخت سبد فروش، محاسبهٔ جمع و کاهش موجودی پس از تأیید فروش
- هشدار کمبود موجودی و گزارش‌های سادهٔ فروش/انبار
- نقش‌های مدیر و فروشنده و ثبت زمان/کاربر عملیات در نسخهٔ کامل

## اجرای نمونهٔ اولیه
بدون نصب وابستگی: فایل `src/index.html` را در مرورگر باز کنید. بارکد نمونه `6260001000011` یا `6260001000028` را در کادر اسکن وارد کنید و Enter بزنید. داده‌ها فقط در حافظهٔ همان صفحه هستند و با تازه‌سازی پاک می‌شوند. برای اتصال اسکنر، اسکنر را در حالت USB-HID/Keyboard قرار دهید.

اگر ترجیح می‌دهید از Python استفاده کنید، `src/app.py` یک سرور محلی ساده ارائه می‌دهد:
```bash
python src/app.py
```
سپس `http://127.0.0.1:8000` را باز کنید. (Python 3؛ سرور فقط فایل نمونه را سرو می‌کند.)

## نقشهٔ راه پیشنهادی
1. تثبیت نیازمندی‌ها و طراحی مدل داده/API.
2. پیاده‌سازی ورود کاربران، کالاها و گردش موجودی با پایگاه داده.
3. پیاده‌سازی فروش و گزارش‌ها، سپس آزمون پذیرش و پشتیبان‌گیری.

جزئیات دامنه و معیارهای پذیرش در [`docs/02-requirements.md`](docs/02-requirements.md) آمده است. وضعیت اسپرینت نمونه در [`docs/sprint-01-report.md`](docs/sprint-01-report.md) ثبت شده.

## انتشار همین پروژه در GitHub
1. از GitHub گزینهٔ **New repository** را بزنید و نامی مثل `trackflow-project` انتخاب کنید. اگر می‌خواهید همین فایل‌ها را بارگذاری کنید، مخزن را خالی بسازید (README/license را خودکار اضافه نکنید).
2. فایل ZIP را از حالت فشرده خارج کنید. وارد پوشهٔ `trackflow-project` شوید؛ خود پوشه را دوباره داخل پوشه‌ای هم‌نام قرار ندهید.
3. **روش وب:** در مخزن GitHub روی **Add file → Upload files** کلیک کنید، همهٔ محتویات پوشه (از جمله `.gitignore`) را بکشید داخل صفحه، صبر کنید بارگذاری تمام شود، پیام commit بنویسید و **Commit changes** را بزنید. اگر فایل‌های داخل پوشه دیده نمی‌شوند، محتویات پوشه را انتخاب کنید، نه خود فایل ZIP را.
4. **روش Git (اختیاری):** در ترمینال داخل پوشه اجرا کنید:
   ```bash
   git init
   git add .
   git commit -m "Initial TrackFlow project"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPOSITORY.git
   git push -u origin main
   ```
   `USERNAME/REPOSITORY` را با آدرس واقعی مخزن عوض کنید. اگر `remote origin already exists` دیدید، به‌جای افزودن دوباره از `git remote set-url origin https://github.com/USERNAME/REPOSITORY.git` استفاده کنید.
5. صفحهٔ مخزن را تازه کنید؛ باید پوشه‌ها و README دیده شوند. برای تغییرات بعدی فایل‌ها را ویرایش کنید و با **Add file → Upload files** یا `git add`, `git commit`, `git push` بفرستید.

> فایل ZIP را مستقیماً در GitHub آپلود نکنید اگر هدف نمایش فایل‌ها و پوشه‌هاست؛ ZIP فقط بستهٔ انتقال است. رمز، کلید API یا اطلاعات واقعی مشتری را commit نکنید.
