## ۱. مقدمه

### ۱.۱ هدف سند
این سند داستان‌های کاربر (User Stories) پروژهٔ **TrackFlow** را تعریف می‌کند. این سیستم برای مدیریت زنجیرهٔ تولید تا فروش قطعات در یک محیط صنعتی طراحی شده است.

### ۱.۲ قالب User Story
هر داستان بر اساس نیاز واقعی ذی‌نفعان پروژه و با قالب زیر نوشته شده است:
> **به‌عنوان** [نقش]، **می‌خواهم** [کاری] **تا** [ارزش].

## ۳. داستان‌های کاربر

### Sprint 1 — کاتالوگ و ثبت موجودی تولید

| ID | User Story | اولویت |
| :---: | :--- | :---: |
| US-01 | به‌عنوان خریدار (مریم) می‌خواهم کاتالوگ قطعات را ببینم تا قطعه مناسب را انتخاب کنم | Must |
| US-02 | به‌عنوان خریدار می‌خواهم بر اساس کد قطعه یا نام جستجو کنم تا سریع‌تر به نتیجه برسم | Must |
| US-03 | به‌عنوان خریدار می‌خواهم جزئیات فنی و بارکد قطعه را ببینم تا از انطباق آن مطمئن شوم | Must |
| US-04 | به‌عنوان خریدار می‌خواهم موجودی لحظه‌ای قطعه را ببینم تا بدانم امکان سفارش وجود دارد یا خیر | Must |
| US-05 | به‌عنوان مسئول انبار (رضا) می‌خواهم قطعات تولیدی جدید را با بارکد ثبت کنم تا موجودی به‌روز شود | Must |
| US-06 | به‌عنوان مسئول انبار می‌خواهم محل استقرار (قفسه/ردیف) هر قطعه را ثبت کنم | Should |

### Sprint 2 — سفارش‌گذاری و مدیریت فروش

| ID | User Story | اولویت |
| :---: | :--- | :---: |
| US-07 | به‌عنوان خریدار می‌خواهم سفارش خرید قطعات را ثبت کنم تا برای کارشناس فروش ارسال شود | Must |
| US-08 | به‌عنوان خریدار می‌خواهم پیش‌فاکتور سفارش خود را مشاهده کنم | Must |
| US-09 | به‌عنوان کارشناس فروش (خانم رضایی) می‌خواهم لیست سفارش‌های جدید را ببینم تا تایید کنم | Must |
| US-10 | به‌عنوان کارشناس فروش می‌خواهم سفارش را پس از بررسی موجودی تایید یا رد کنم | Must |
| US-11 | به‌عنوان کارشناس فروش می‌خواهم برای سفارش‌های تایید شده، فاکتور نهایی صادر کنم | Must |

### Sprint 3 — ترخیص و گزارش‌گیری

| ID | User Story | اولویت |
| :---: | :--- | :---: |
| US-12 | به‌عنوان مسئول انبار می‌خواهم بارکد قطعات بارگیری شده را اسکن کنم تا با فاکتور تطبیق داده شود | Must |
| US-13 | به‌عنوان مسئول انبار می‌خواهم حواله خروج صادر کنم تا کالا رسماً از انبار خارج شود | Must |
| US-14 | به‌عنوان کارشناس فروش می‌خواهم گزارش فروش روزانه و ماهیانه قطعات را مشاهده کنم | Should |
| US-15 | به‌عنوان مدیر فروش می‌خواهم هشدار کمبود موجودی قطعات پرفروش را دریافت کنم | Could |

## ۴. تفکیک بر اساس Sprint

- **Sprint 1 (هفته‌های ۱-۵):** تمرکز بر زیرساخت کاتالوگ و ثبت ورودی انبار (US-01 تا US-06)
- **Sprint 2 (هفته‌های ۶-۱۱):** تمرکز بر فرایند سفارش‌گذاری و تایید فروش (US-07 تا US-11)
- **Sprint 3 (هفته‌های ۱۲-۱۴):** تمرکز بر خروج کالا، بارکدینگ نهایی و گزارش‌گیری (US-12 تا US-15)

## ۶. معیار پذیرش نمونه (Acceptance Criteria)

### US-05 — ثبت قطعات تولیدی جدید (رضا)
**به‌عنوان:** مسئول انبار
**می‌خواهم:** بارکد قطعه را اسکن کنم
**تا:** موجودی انبار به‌صورت خودکار افزایش یابد

**معیار پذیرش:**
- [ ] سیستم پس از اسکن، شناسه یکتا (UID) را شناسایی کند.
- [ ] تعداد ورودی باید با موجودی فعلی جمع شود.
- [ ] نام کاربر (رضا) و زمان ثبت در لاگ سیستم ذخیره شود.
