## ۱. مقدمه

### ۱.۱ هدف سند
این سند پرسوناهای کاربران هدف پروژهٔ **TrackFlow** را تعریف می‌کند. هدف آن ایجاد درک عمیق از نیازها، اهداف و دردهای کاربران (مدیر فروشگاه، فروشنده و انباردار) است تا تصمیم‌گیری‌های طراحی و توسعه بر پایهٔ آن‌ها انجام شود.

### ۱.۲ چرا پرسونا؟
پرسونا یک **نمایندهٔ فرضی** از یک گروه کاربری است که با داده‌های واقعی ساخته می‌شود. پرسونا کمک می‌کند:
- تیم توسعه بداند برای **چه کسی** سیستم را می‌سازد.
- از تلهٔ «طراحی برای همه» پرهیز شود.
- اولویت‌بندی ویژگی‌ها بر پایهٔ نیاز واقعی کاربران باشد.

### ۱.۳ روش‌شناسی
پرسوناها بر پایهٔ مشاهدات میدانی فرضی، مصاحبه با کسب‌زارهای کوچک، بررسی ابزارهای مدیریت انبار و استانداردهای طراحی نرم‌افزار تجاری تدوین شده‌اند. (توجه: مشخصات دموگرافیک زیر فرضی و جهت‌دهندهٔ طراحی‌اند).

## ۲. پرسونا ۱ — نرگس (مدیر فروشگاه / ادمین)

### مشخصات دموگرافیک
| ویژگی | مقدار |
| :---: | :---: |
| نام | نرگس احمدی |
| سن | ۴۱ سال |
| جنسیت | زن |
| شغل | مالک فروشگاه لوازم خانگی و خرد |
| محل زندگی | تهران |
| تحصیلات | کارشناسی |
| مهارت فنی | متوسط (راحت با ابزارهای ساده، فراری از سیستم‌های پیچیده) |
| وضعیت تأهل | متأهل، یک فرزند |

### نقل‌قول
> «موجودی انبارم دوهزار قلم کالا دارد؛ با نرم‌افزارهای پیچیدہ وقتم تلف می‌شود و حوصلهٔ فرم‌های شلوغ را ندارم.»

### اهداف
- بداند چه کالایی کم شده و چه زمانی باید سفارش مجدد دهد.
- قیمت‌ها و اطلاعات کالا را به‌سادگی مدیریت کند.
- فروش روزانه و گردش مالی کلی فروشگاه را پایش کند.

### دردها
- شمارش دستی موجودی بسیار وقت‌گیر و پرخطاست.
- نمی‌داند اختلاف موجودی دقیقاً از کدام عملیات (فروش، جابه‌جایی یا خطای انسانی) آمده است.
- با نرم‌افزارهای حسابداری و انبارداری سنتی و پر از منوی پیچیده ارتباط برقرار نمی‌کند.

### نیازها
- داشبورد ساده، تمیز و فارسی با دسترسی سریع به گزارش‌ها.
- هشدار خودکار کمبود موجودی پیش از اتمام کامل کالا.
- ثبت رسید با مقدار، تاریخ و دلیل مشخص و قابل ردیابی.
- امکان تعریف کالای جدید بدون نیاز به پشتیبانی فنی.

### سناریوی استفاده
> صبح پس از ورود به فروشگاه، با تبلت وارد سامانه TrackFlow می‌شود.
> نگاهی به هشدار کالاها می‌اندازد، قیمت دو قلم لوازم خانگی را به‌روزرسانی می‌کند
> و گزارش فروش روز گذشته را بررسی می‌کند.

## ۳. پرسونا ۲ — امیر (فروشنده / اپراتور صندوق)

### مشخصات دموگرافیک
| ویژگی | مقدار |
| :---: | :---: |
| نام | امیر رضایی |
| سن | ۲۶ سال |
| جنسیت | مرد |
| شغل | فروشنده و متصدی صندوق |
| محل زندگی | تهران |
| تحصیلات | دانشجوی کارشناسی |
| مهارت فنی | بالا |

### نقل‌قول
> «مشتری پشت صندوق صف کشیده؛ اسکنر USB دست من است و سرعت و خطای صفر برایم از هر چیزی مهم‌تر است.»

### اهداف
- پیدا کردن سریع کالا و ثبت اقلام خرید در سریع‌ترین زمان ممکن.
- افزودن چندین قلم کالا به یک فاکتور فروش بدون معطلی.
- اطمینان از صحت قیمت‌ها و عدم فروش بیش از موجودی واقعی انبار.

### دردها
- جست‌وجوی دستی نام کالا یا بارکد کند در ساعات شلوغی فروشگاه موجب کلافگی می‌شود.
- اشتباه در ورود دستی قیمت یا کد کالا اعتماد مشتری را مخدوش می‌کند.
- نرم‌افزارهای کند موجب تشکیل صف طولانی جلوی صندوق می‌شوند.

### نیازها
- فوکوس خودکار روی فیلد ورودی اسکنر بارکد (USB Barcode Scanner).
- پیام خطای واضح و صریح در صورت ناموجود بودن کالا.
- سبد خرید قابل ویرایش با امکان حذف یا تغییر تعداد اقلام.
- جلوگیری خودکار از ثبت فروش بیشتر از موجودی انبار.

### سناریوی استفاده
> در ساعت اوج شلوغی مغازه، با بارکدخوان پشت صندوق ایستاده است.
> پشت‌سر هم بارکد اجناس را اسکن می‌کند؛ اقلام بلافاصله با قیمت و موجودی درست
> به سبد اضافه می‌شوند و فاکتور نهایی با یک کلید صادر می‌شود.

## ۴. پرسونا ۳ — سارا (انباردار)

### مشخصات دموگرافیک
| ویژگی | مقدار |
| :---: | :---: |
| نام | سارا کریمی |
| سن | ۳۴ سال |
| جنسیت | زن |
| شغل | انباردار و مسئول دریافت محموله |
| محل زندگی | تهران |
| تحصیلات | کاردانی |
| مهارت فنی | متوسط |

### نقل‌قول
> «هر ورودی و خروجی باید حساب‌کتاب داشته باشد؛ اصلاح موجودی بدون توضیح، کل انبار را به هم می‌ریزد.»

### اهداف
- ثبت سریع و بدون خطای ورود محموله‌های جدید به انبار.
- ردیابی و تطبیق دقیق میان مقدار فیزیکی کالا و آمار سیستمی.
- ثبت مستندات گردش کالا و دلایل تغییرات موجودی.

### دردها
- اصلاحات دستی موجودی بدون ذکر دلیل، پیگیری مغایرت‌ها را غیرممکن می‌کند.
- نبود سیستم یکپارچه برای جست‌وجوی بارکد قطعات در قفسه‌ها.

### نیازها
- ثبت سریع رسید ورود کالا با درج مقدار، تاریخ و علت دقیق.
- ابزار جست‌وجوی سریع بارکد برای انبارگردانی.
- گزارش گردش کالای شفاف و تاریخ‌دار.

### سناریوی استفاده
> صبح محمولهٔ جدید یخچال‌ها را تحویل می‌گیرد.
> با اسکن بارکد کارتن‌ها، تعداد دریافتی را در سیستم ثبت می‌کند
> و گزارش تطبیق موجودی را برای مدیر (نرگس) ارسال می‌کند.

## ۵. دسترس‌پذیری و محیط عملیاتی
* **محیط کار:** ممکن است کاربر با نور محیطی بالا، صفحهٔ نمایش کوچک (تبلت یا لپ‌تاپ قدیمی) یا صرفاً با صفحه‌کلید (بدون ماوس در بخش صندوق) کار کند.
* **رابط کاربری:** فیلد فعال (Focus) و پیام‌های خطا باید کاملاً واضح و برجسته باشند؛ رنگ نباید تنها ابزار انتقال وضعیت (Accessibility) باشد.
* **سخت‌افزار:** بارکدخوان‌های متداول USB مانند صفحه‌کلید عمل کرده و پس از خواندن بارکد کاراکتر `Enter` ارسال می‌کنند که سامانه باید آن را به صورت خودکار مدیریت کند.
