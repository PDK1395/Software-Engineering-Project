## ۱. مقدمه

### ۱.۱ هدف سند
این سند پرسوناهای کاربران هدف پروژهٔ  **مدیریت انبار و فروش** را تعریف می‌کند. هدف آن ایجاد درک عمیق از نیازها، اهداف و دردهای کاربران (مدیر فروشگاه، فروشنده و انباردار) است تا تصمیم‌گیری‌های طراحی و توسعه بر پایهٔ آن‌ها انجام شود.

### ۱.۲ چرا پرسونا؟
پرسونا یک **نمایندهٔ فرضی** از یک گروه کاربری است که با داده‌های واقعی ساخته می‌شود. پرسونا کمک می‌کند:
- تیم توسعه بداند برای **چه کسی** سیستم را می‌سازد.
- از «طراحی برای همه» پرهیز شود.
- اولویت‌بندی ویژگی‌ها بر پایهٔ نیاز واقعی کاربران باشد.

### ۱.۳ روش‌شناسی
پرسوناها بر پایهٔ مشاهدات میدانی فرضی، مصاحبه با کسب‌زارهای کوچک، بررسی ابزارهای مدیریت انبار و استانداردهای طراحی نرم‌افزار تجاری تدوین شده‌اند. (توجه: مشخصات دموگرافیک زیر فرضی و جهت‌دهندهٔ طراحی‌اند).

## ۲. پرسونا ۱ — خانم رضایی (کارشناس فروش)

### مشخصات دموگرافیک
| ویژگی | مقدار |
|--------|-------|
| نام | فاطمه رضایی |
| سن | ۴۲ سال |
| جنسیت | زن |
| شغل | صاحب فروشگاه لوازم خانگی |
| محل زندگی | کاشان |
| تحصیلات | دیپلم |
| مهارت فنی | متوسط |
| وضعیت تأهل | متأهل، دو فرزند |

### نقل‌قول نمونه
> «برای مدیریت فروش باید بتوانم سفارش‌ها را پیگیری کنم و گزارش‌ها را در دسترس داشته باشم.»

### اهداف
- کنترل و پیگیری سفارش‌های فروش.
- دسترسی به گزارش‌های مرتبط با فروش.
- هماهنگی میان فروش و موجودی انبار.
- اطمینان از ثبت درست اطلاعات فروش و سفارش‌ها.

### دشواری‌ها
- پراکندگی اطلاعات، پیگیری سفارش‌ها را دشوار می‌کند.
- ناهماهنگی میان فروش و موجودی انبار می‌تواند باعث خطا در پاسخ‌گویی شود.
- نبود گزارش‌های روشن، بررسی وضعیت فروش را زمان‌بر می‌کند.

### نیازها
- نمایش متمرکز سفارش‌ها و وضعیت هر سفارش.
- دسترسی به گزارش‌های فروش.
- مشاهدهٔ اطلاعات موجودی کالا هنگام پیگیری سفارش.
- امکان پیگیری سوابق سفارش‌ها و تغییر وضعیت آن‌ها.

### سناریوی استفاده
> خانم رضایی وارد سامانه می‌شود و سفارش‌های ثبت‌شده را بررسی می‌کند. سپس وضعیت سفارش‌ها را پیگیری می‌کند و برای پاسخ‌گویی به درخواست‌های مشتریان، گزارش فروش و موجودی کالاهای مرتبط را می‌بیند.

## ۳. پرسونا ۲ — مریم (خریدار قطعات)

### مشخصات دموگرافیک
| ویژگی | مقدار |
|--------|-------|
| نام | مریم احمدی |
| سن | ۳۲ سال |
| جنسیت | زن |
| شغل |خریدار قطعات |
| محل زندگی | تهران |
| تحصیلات | کارشناسی |
| مهارت فنی | بالا |
| وضعیت تأهل | متأهل، یک فرزند |

### نقل‌قول نمونه
> «ثبت کالا با بارکد کمک می‌کند موجودی را سریع‌تر و با خطای کمتری وارد کنم.»

### اهداف
- ثبت دقیق ورود و خروج کالاها.
- به‌روزرسانی موجودی هنگام دریافت یا جابه‌جایی کالا.
- پیدا کردن سریع کالا با استفاده از بارکد.
- پیگیری مغایرت میان موجودی فیزیکی و موجودی ثبت‌شده.

### دشواری‌ها
- ثبت دستی کالاها می‌تواند زمان‌بر و مستعد خطا باشد.
- پیدا کردن علت مغایرت موجودی بدون سابقهٔ عملیات دشوار است.
- تأخیر در ثبت ورود یا خروج کالا باعث ناهماهنگی اطلاعات انبار می‌شود.

### نیازها
- ثبت و جست‌وجوی کالا با بارکد.
- نمایش روشن تعداد موجودی هر کالا.
- ثبت سابقهٔ ورود، خروج و اصلاح موجودی.
- مشخص بودن کاربر، زمان و دلیل تغییر موجودی.

### سناریوی استفاده
> رضا محمولهٔ جدیدی را تحویل می‌گیرد. بارکد کالاها را اسکن می‌کند، تعداد دریافتی را ثبت می‌کند و موجودی به‌روزشده را در سامانه بررسی می‌کند. اگر مغایرتی ببیند، سابقهٔ عملیات همان کالا را پیگیری می‌کند.

## ۴. پرسونا ۳ — رضا (مسئول انبار)

### مشخصات دموگرافیک
| ویژگی | مقدار |
|--------|-------|
| نام | رضا کریمی |
| سن | ۲۸ سال |
| جنسیت | مرد |
| شغل | انباردار |
| محل زندگی | کاشان |
| تحصیلات | دیپلم |
| مهارت فنی | پایین |

### نقل‌قول نمونه
> «پیش از خرید باید مشخصات کالاها را در کاتالوگ بررسی کنم تا قطعهٔ مناسب را انتخاب کنم.»

### اهداف
- بررسی مشخصات کالاها پیش از خرید.
- انتخاب قطعهٔ متناسب با نیاز فروشگاه.
- اطلاع از موجودی کالا و اطلاعات مرتبط با آن.
- کاهش خطا در انتخاب یا سفارش قطعات.

### دشواری‌ها
- اطلاعات ناکامل کالا انتخاب درست را دشوار می‌کند.
- پیدا کردن کالای موردنظر در میان اقلام متعدد زمان‌بر است.
- ناآگاهی از موجودی به‌روز می‌تواند باعث سفارش نامناسب شود.

### نیازها
- کاتالوگ قابل جست‌وجو با مشخصات روشن کالا.
- دسترسی به اطلاعات شناسایی کالا، از جمله بارکد.
- مشاهدهٔ وضعیت موجودی هنگام بررسی کالا.
- امکان مقایسهٔ مشخصات قطعات مرتبط.

### سناریوی استفاده
> مریم برای تهیهٔ قطعات موردنیاز، کاتالوگ کالاها را بررسی می‌کند. با جست‌وجوی نام یا بارکد، مشخصات چند قطعه و وضعیت موجودی آن‌ها را می‌بیند و گزینهٔ مناسب را برای سفارش انتخاب می‌کند.

## ۵. دسترس‌پذیری و محیط عملیاتی

- **بارکدخوان:** بارکدخوان باید امکان واردکردن سریع شناسهٔ کالا را فراهم کند. رفتار آن، از جمله ارسال خودکار کلید `Enter` پس از اسکن، باید با سخت‌افزار واقعی آزموده شود.
- **نمایش وضعیت:** موجودی، خطاها و وضعیت سفارش‌ها باید با متن روشن نمایش داده شوند؛ رنگ به‌تنهایی نشانهٔ وضعیت نباشد.
- **ورودی‌ها:** ثبت اطلاعات باید با صفحه‌کلید نیز امکان‌پذیر باشد و فیلد فعال به‌وضوح مشخص شود.
